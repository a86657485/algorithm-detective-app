# 算法小侦探事务所

五年级信息科技《第 2 课 算法认识与体验》课堂互动闯关应用 + 结业考核 + 教师实时数据看板。

学生以"算法小侦探"的身份连破五个案件，在动手操作中认识算法的含义、掌握
**输入 → 处理 → 输出** 的基本流程；通关后进入 **20 题结业考核**，
教师可在同一套系统里 **按班级实时查看全班进度与成绩**。

---

## 一、最省事的用法（推荐）

双击项目目录里的 **`启动服务.bat`**。

脚本会自动构建前端并启动服务，窗口里会打印两行关键地址：

```
Student devices : http://10.9.129.17:3001/          ← 把这个发给学生
Dashboard       : http://localhost:3001/#/dashboard  ← 老师看数据
```

- 学生机浏览器打开 `http://<教师机IP>:3001/`，先选班级 → 再选自己的姓名 → 开始闯关
- 老师浏览器打开 `http://localhost:3001/#/dashboard`，口令 `teacher`
- **使用期间不要关闭那个黑色窗口**；结束时直接关掉即可，数据已落盘

### 防火墙（已经配置好，一般不用再管）

Windows 防火墙默认会拦截外部电脑访问 3001 端口。本机已经添加了永久放行规则：

```
规则名：AlgoDetective Class Server (TCP 3001)
方向：入站  协议：TCP  端口：3001  动作：允许
配置文件：域 / 专用 / 公用（全开）  状态：已启用
```

换一台教师机、或重装系统后需要重建，双击 **`开放防火墙端口.bat`**
→ 弹出「用户账户控制」时点**是** 即可（只需一次，重启后依然有效）。

验证是否生效：

```powershell
netsh advfirewall firewall show rule name="AlgoDetective Class Server (TCP 3001)"
```

看不到规则、或学生机仍然打不开，按顺序排查：

1. 教师机浏览器打开 `http://localhost:3001/` 能不能通？不通说明服务没起来
2. 教师机打开 `http://本机IP:3001/` 能不能通？不通说明服务没监听对外网卡
3. 学生机 `ping 教师机IP` 通不通？不通说明不在同一网段，需要找网管开路由
4. 上面都对但学生机还打不开 → 检查是不是装了第三方安全软件（360、火绒等）另有一层拦截

## 二、命令行方式

```bash
npm install         # 首次运行
npm run serve       # = 构建 + 启动服务（等价于双击 bat）
npm run build       # 只构建前端到 dist/
npm start           # 只启动服务（需先 build）
npm run dev         # 前端热更新调试（需另开一个窗口跑 npm run dev:server）
npm run dev:server  # 只启动后端 API（端口 3001）
```

改端口 / 改口令：

```bash
set PORT=8080
set TEACHER_PASSWORD=mypassword
npm start
```

## 三、功能地图

| 视图 | 入口 | 说明 |
| --- | --- | --- |
| 登录页 | 打开应用即是 | 选班级（501~504，共 212 人）→ 搜名字 → 选姓名进入 |
| 五个关卡 | 登录后自动进入 | 厨房现场 / 数字迷宫 / 密室测量 / 24 点终局 / 侦探证 |
| 结业考核 | 通过 24 点后自动进入 | 独立一页 20 道单选题，提交即判分并给教材依据解析 |
| 教师看板 | `#/dashboard` | 按班级实时汇总，无需刷新 |

### 教师看板能看到什么

- 汇总卡：应到人数 · 已进入 · 当前在线 · 已通关 5 关 · 已完成考核 · 考核平均分（含最高/最低）
- 班级切换：全部 / 501 / 502 / 503 / 504，还能按姓名搜索、只看未考核、按进度或分数排序
- 学生明细：进入时间、关卡进度 `n/5`、游戏总分、考核得分、状态（未进入 / 闯关中 / 待考核 / 已考核）
- 各关卡完成情况：每一关的完成人数与完成率
- 最易错的 5 道题：正确率从低到高排，讲评时优先看这几题
- 班级对比：各班进入、通关、考核人数与平均分

数据通过 SSE 实时推送，学生那边一提交，看板立刻更新。

## 四、考核题覆盖范围

20 道单选题分布在 6 个知识点上，每题都附教材依据：

| 知识点 | 题数 |
| --- | --- |
| 算法的含义与特征 | 3 |
| 输入 · 处理 · 输出三要素 | 5 |
| 西红柿炒鸡蛋案例 | 3 |
| 自然数相加的步骤与进位 | 4 |
| 24 点游戏规则与策略 | 3 |
| 面积计算与算法思想 | 2 |

题库在 `shared/quiz-data.mjs`，**前端取题、后端判分共用这一份**，
所以题面和答案永远一致。要加题或改题，只改这一个文件，然后重新 `npm run build`。

## 六、数据与备份

- 全部数据在 **`server/data/db.json`**，一个文件，可直接复制备份
- 结构：`{ students: { "501::陈远晴": {...} }, meta: { updatedAt } }`
- 每位学生记录：进入时间、最后活跃时间、五个关卡的得分/用时、徽章、考核成绩与逐题作答
- 文件损坏时会自动备份为 `db.corrupt.<时间戳>.json` 并重建，服务不会崩
- 想清空重来：停掉服务，删掉 `db.json`，再启动

## 七、断网也能用

学生的操作先存本地浏览器（`localStorage`），同时进入上报队列：

- 发不出去就先留在队列里，`online` 事件或每 15 秒自动补传
- 所以机房中途断网，学生可以照常把游戏和考核做完，联网后数据自动补上
- 唯一影响：断网期间看板上看不到这位同学的实时进度（联网后会补齐）

## 八、接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/roster` | 班级与名单 |
| POST | `/api/login` | 学生进入登记 |
| POST | `/api/progress` | 进度快照上报 |
| GET | `/api/quiz` | 下发 20 题（不含答案） |
| POST | `/api/quiz` | 提交答卷，**服务端判分** |
| POST | `/api/teacher/login` | 口令换 token |
| GET | `/api/dashboard?classId=&token=` | 聚合数据 |
| GET | `/api/stream?token=` | SSE 实时推送 |
| GET | `/api/health` | 健康检查 |

## 九、兼容性

- 建议视口 ≥ 1024×768（已实测该分辨率下无横向溢出）
- 界面零外部 CDN，断网可正常显示
- 后端只用 Node 内置模块，机房没有外网也能跑
